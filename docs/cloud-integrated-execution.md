## 已实施的 DSH 能力迁移

| 原 DSH 实际接口/实现 | 小云内置对应 | 验收依据 |
|---|---|---|
| Ubuntu / Node / PRoot | APK 内同源 payload、原生管道启动，首次哈希校验与解压，后续复用 | 原生进程实际返回 Linux / Node v24.18.1 |
| working_directory / workspace | 持久项目 ID、项目浏览、明确 cwd、跨任务写入与进程归属 | 多项目实际运行、异会话停止被拒绝 |
| read / write / edit / str_replace_editor | 哈希保护读写、唯一替换、unified patch、编辑前后差异 | 明确错误、多文件修改、修复后退出 0 |
| glob / grep | 项目路径 glob、内容搜索、Linux/Node 原有搜索能力 | 实际项目文件和匹配结果；不会假定 rg 已安装 |
| read_image | 实际 PNG/JPEG/WebP 输入当前模型；图像和截图只在本轮内存上下文 | 节点不足时使用；模型视觉支持须真实 API 接受 |
| bash / job_output / job_list / job_kill | 独立命令、持续 stdout/stderr、退出码、真实 stdin、进程组及继承标识子进程停止 | 长任务、输入、setsid 子进程心跳停止、重启未知不重放 |
| present | 显式最终清单、只读交付版本、格式/哈希核对、分组卡片、预览/系统打开/SAF/分享 | 20 个过程文件仅交付 2 个最终文件；版本、缺失、部分失败 |
| files/projects、files/home、会话 JSONL/zstd | 同签名只读 ZIP、逐文件校验、可恢复备份、旧工作区和只读会话浏览 | 原数据不删除、不改主应用现有模型配置 |
| 旧插件启动/模型代理会话 | 小云现有模型授权与流式链路直接调用内置工具；迁移后旧 launcher/市场入口隐藏，旧 DSH 服务绑定被拒绝 | 无需打开 DSH 页面；独立包只用于一次性数据导出 |

实际基线只有 Node/npm、bash/sh。原 DSH payload 没有 Python、Git、C/C++ 编译器、make、rg、curl、zip/unzip，不能宣称预装。Node 原生模块和内置 OOXML/ZIP 辅助库支持真实表格、文档与项目包；其他语言/依赖需要在真实环境准备后才能使用。PRoot 不构成对恶意代码的安全沙箱；本实现的多任务归属、路径检查和停止保护不等于任意代码安全隔离。Android 8 以下保留主应用功能，但不启动与原 DSH 同样要求 Android 8 的 Linux 环境。

## 运行与交付规则

普通对话和即时工具不新增长期待办。执行记录由对话所属引擎发布到应用级执行状态；浮岛、动画、任务页和通知只消费此状态，显示切换不派发动作。暂停只在实际动作边界提供；停止取消后续队列、等待和所属编程进程，未证实的副作用保留待核对。

每次编程计划固定项目、模型与既有用量预算。WorkManager 的独立触发/租约/防重仍由原 SQLite 存储管理；停止/超时会撤销所属运行的内置进程。后台 UI 仅在真实无障碍连接、屏幕可操作、目标软件已授权时使用同一后端；条件不足等待，不自动启动权限页或把小云带到前台。

`coding.deliver.prepare` 的明确清单才进入最终文件组，不扫描目录或推断聊天路径。每个成功文件保存在应用私有持久产物目录，具有独立 ID、哈希及版本。外部保存或分享属于另外一次用户操作，取消不会改变生成结果。XLSX/DOCX 内置内容预览有明确行列/格式限制；保留完整原文件，可通过系统查看器打开或保存。

资源的最终 SHA 以 `third_party/cloud-runtime/payload-*.json` 为准；`provenance/` 保留原 DSH 构建的历史依赖来源，不能把其中旧 payload 摘要当成本次最终归档摘要。准备工具 `tools/prepare_cloud_runtime.py --abi … --source …` 在构建前再次核对实际资源。

## 0.2.92 空白工作簿与模型输出修复

用户真机“生成一个空白的Excel”失败时，已完成的只有打开项目和工具探测，尚无最终文件清单；随后模型尝试编写长段 XLSX/ZIP 底层代码，动作 JSON 校验连续失败。原始失败响应和结束原因没有持久化，不能将旧请求的精确截断位置冒称已确认。代码审查同时确认了两个缺口：独立模型连接的助手请求被额外限制到最多 4096 tokens；ChatEvent.limited 没有进入执行循环，截断会被统一说成无效动作。

新增 coding.workbook.create 复用真实 OOXML 写入库，按明确项目/路径创建一个或多个空工作表，默认 Sheet1；仍执行 SHA 覆盖保护、原始版本留存、临时文件原子写入、回读和持久请求防重。随后经既有 coding.deliver.prepare 完成格式/哈希核对和文件卡片，未为此绕过最终交付规则。空白工作簿不再需要 Python 或模型手写压缩包代码。

独立模型连接现在遵守原有输出设置；定时计划的显式预算及账号接口本来的服务上限保持。截断依据实际协议标记识别，拒绝派发残缺动作，最多尝试改用简短完整动作；仍失败时给出输出上限原因。格式错误和协议确认的截断分开记录，不保存新增原始响应/凭据。702 项 Flutter 回归通过；7 项真实 Android 编程测试通过，包括有效 XLSX/一个空表/0 填充单元格/覆盖保护/真实交付预览，PC openpyxl 独立解析通过。完整真机复测结果见 E:/zzz/ops/skivu-blank-workbook-fix-20261109。


## 0.2.93 手机文件与系统打开

用户要求文件默认交给手机对应应用，并在文件管理中实际可见。新成果完成格式/哈希核对后，自动通过 MediaStore.Downloads 写入 Download/Skivu，使用 IS_PENDING 隐藏未写完的行，关闭后回读大小及 SHA，再发布。依据 [Android 共享存储说明](https://developer.android.com/training/data-storage/shared/media)，Android 10 及以上可管理应用自己创建的 Downloads 文件，不新增全盘存储权限；更早系统通过已有“另存为”选择位置，未伪称自动保存成功。

“打开”使用正确 MIME、content URI 和临时读写授权的 ACTION_VIEW，尊重系统默认应用；“选择打开方式”才显式使用系统选择器。依据 [Android 应用间文件打开说明](https://developer.android.com/training/package-visibility/use-cases)，通过 URI 授权交给目标应用读取。原内容预览保留在“预览原始成果”，另存为和分享仍是独立操作；分享仅启动选择器，不自动发送。

卡片统计并显示默认下载副本及实际路径；“另存为”的其他位置单独提示，并在可读取时回读验证。自动保存失败时保留原始成果，报告 phone_save 失败，不把私有目录当作已保存到下载。目录只接收显式最终清单，不导出项目缓存、脚本或日志。
