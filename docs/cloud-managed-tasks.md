# 小云与任务页联动（0.2.89）

## 当前行为

小云、今天、任务以及“定时”筛选共用 `PersonalSpaceStore`。定时筛选仍然只是查看填写了时间的任务，不注册后台工作，不启用系统提醒，也不会自动执行旧任务。

- `tasks.create/list/get/update/complete/archive` 管理同一份本地数据。
- 仅在用户明确需要待办、记录或继续跟进时新增任务。普通回答、查询、临时设备操作不自动加入任务。
- `complete` 设置明确的完成值，`archive` 设置明确的归档值，不使用翻转操作。
- 模型修改前读取实际任务 ID 和 revision。并发修改冲突返回失败，不能覆盖另一处的新版本。
- 任务页“交给小云”给当前消息附上任务引用。引用可移除，不会直接发消息或执行任务；下一轮不会自动沿用。
- 小云结果卡片“查看任务”打开同一条记录。手动改动本地待办后，任务卡片读取最新标题、日期、完成及归档状态。

## 外部操作的结果卡片

原来手机时钟等操作仍然走原设备工具，不再引入小云自建闹钟。只有实际已验证或用户已确认完成的写操作才显示完成卡片。纯查询、打开软件及只确认 shell 进程退出不会生成完成卡片。

“加入任务”只把结果快照保存为一条**已完成任务**，附上执行来源摘要和安全的对应软件入口类型。它不会重放设备操作，不会调用系统时钟，不会因为结果含时间就创建提醒。

同一执行结果通过来源指纹和原子回执去重，重启或归档后再次点击仍指向原记录。归档、完成或编辑这条本地记录不会修改系统软件。没有取得外部对象的真实 ID 时不构造虚假的闹钟/日历资源关联；卡片中的原始结果快照也不随本地任务重命名而变成“外部软件已修改”。

## 存储和故障

沿用原个人空间键，支持读取 v1。首次写入 v2 前将旧 v1 原文保存在 `skivu.main.personal-space.backup.v1`；记忆数据保持。存档读错时不覆盖原内容。

任务及本次请求的 `{id,digest,taskId}` 回执在同一次写入中提交。只有持久化成功后才发布界面变化和 verified 结果。保留最近 256 条最小私有回执，不把每次执行新增成任务记录。结果来源指纹保留在任务中，不随回执裁剪丢失。

同一请求 ID 不允许换参数；重试返回当前记录，不重做旧修改。相同活跃待办有内容去重，已完成的普通待办允许用户明确再创建。存储写操作串行；取消会阻止尚未提交的排队修改。已经进入持久化的提交不伪装成回滚，后续查询可以看到实际状态。应用中断后不会自动重放旧对话。

## 后续边界

真实后台重复执行、精确定时、外部资源的可验证修改/取消不属于这一版已提供的能力。接入后台 worker 前应迁移到支持跨执行环境事务的统一存储，并实现租约、每次触发去重、过期处理和读取实际资源的验证流程，不能仅给现有日期字段加一个自动执行开关。

验证包括本地存储/助手循环回归，以及 Android QA 包中的完整联动流程。模拟模型响应走本机 HTTP；系统结果卡片使用受控回执，不创建真实闹钟或产生付费模型请求。
